Section B · Product

Product Surface

Together's product spans inference API, dedicated endpoints, fine-tuning, and full training clusters. The breadth lets customers grow with the platform from initial experimentation to production scale.

Inference API

The flagship product. Per-token, OpenAI-API-compatible inference on a curated catalog of open-source models. Customers point their OpenAI client at Together's endpoint, change the model name, and they're running.

The docs say the platform runs 100+ open-source models. The catalog includes:

  • Kimi, GLM, MiniMax, Qwen3.x and DeepSeek V4.x, the families that lead the serverless price list as of November 2026.
  • OpenAI's gpt-oss and NVIDIA Nemotron models.
  • The Llama line, now mostly a Llama 3 8B Lite row on the serverless list. Llama 4 and Llama 3.3 70B still appear in the fine-tuning list. Mixtral no longer appears in the serverless list.
  • Various fine-tuned variants and instruction-tuned versions.
  • Specialized models (code, math, vision-language).

The API is the easiest entry point for any customer who's been using OpenAI's API and wants to try open-source alternatives.

Dedicated endpoints

The docs describe three inference modes that share one API (as of November 2026). Serverless is the shared per-token fleet. Provisioned throughput reserves capacity in throughput units for a stock model, with a defined SLA on throughput and reliability. Dedicated model inference runs one model on GPUs reserved for you and bills per GPU-minute by hardware, which the docs say is cheaper than per-token billing at high utilization. Dedicated container inference serves custom models. Batch jobs run at up to 50% off serverless rates.

Provisioned throughput and dedicated inference are the bridge between the pure per-token API and full dedicated GPU rental. Customers who outgrow the API but don't want to manage their own infrastructure land here.

Fine-tuning

Together provides managed fine-tuning for open-source models. The customer uploads training data, picks a base model, runs the fine-tune; Together handles the infrastructure and returns a deployable model. The result can be served via the API.

The fine-tuning product captures customers who want to customize models without building training infrastructure themselves.

Training clusters

For customers doing serious training (not just fine-tuning), Together offers dedicated training clusters. The GPU clusters docs say nodes of every GPU type connect over 3.2 Tb/s InfiniBand for multi-node training, and Together provides operational support during the training run.

The training-cluster product overlaps with what CoreWeave and Crusoe offer. Together's positioning is different — it's bundled with the broader inference / fine-tuning lifecycle.

Code / agentic offerings

Together has invested in code-specific and agentic-AI products:

  • Hosted code-generation models, plus a code sandbox and a code interpreter API.
  • Specialized agentic stacks for autonomous AI workflows.
  • Integration with developer tooling.

These vertical products extend Together's TAM beyond raw inference into specific use-case platforms.

Software stack

Together's inference stack reflects the research lineage:

  • FlashAttention integration for attention efficiency.
  • Custom kernels for high-throughput serving.
  • Speculative decoding optimizations.
  • Quantization options for memory efficiency.
  • Batching and scheduling for high throughput at controlled latency.

The performance advantage from this stack vs naive serving is significant. Together can charge competitive prices and still maintain margin because the platform extracts more throughput per GPU than less-optimized alternatives.

✓ Check yourself

Answer from memory before opening each one.

  1. A SaaS team already uses the OpenAI SDK. What do they change to try an open model on Together, and what must they still verify?

    Show answer

    They change the API key, the base URL and the model name. They must still check output quality on their own prompts, support for features such as tool calling and structured output, latency and rate limits, because compatibility covers the API shape and not the model's behaviour. See inference API.

  2. When does a dedicated endpoint beat per-token pricing, and what goes wrong if you move too early?

    Show answer

    It wins when traffic is high and steady enough to keep the reserved GPUs busy, and it gives steadier latency. Move too early and you pay for idle hours that per-token billing would never have charged. See dedicated endpoints.

  3. A GPU costs $3 an hour and serves 3,000 tokens per second. What is the cost per million tokens, and what happens if the software stack doubles throughput?

    Show answer

    The GPU produces 10.8M tokens an hour, so a million tokens cost about $0.28. Doubling throughput halves that to about $0.14. This is how the stack lets Together hold market prices and still keep margin. See software stack.

  4. Why would a team train on Together instead of on a pure GPU cloud, given the product overlaps with CoreWeave and Crusoe?

    Show answer

    Training there continues into fine-tuning and serving on the same platform, with operational help during the run. A pure GPU cloud can still win on cluster scale and price, so the bundle matters most to teams that will deploy on Together anyway. See training clusters.

  5. Why is managed fine-tuning a good way to keep customers once they have started with the API?

    Show answer

    A fine-tuned model is trained, hosted and served on the platform, so the customer has invested data and effort in something that runs there. Moving away means re-hosting and re-validating. See fine-tuning.

Takeaway

  • The flagship is per-token inference on a curated catalog of open models, through an OpenAI-compatible API, so a switch means changing the key, the base URL and the model name.
  • Provisioned throughput and dedicated endpoints sit between the per-token API and raw GPU rental: reserved capacity that Together operates, billed per throughput unit or per GPU-minute, for customers with high or steady load.
  • Managed fine-tuning takes your data and a base model and returns a model you can serve through the same platform.
  • Training clusters on InfiniBand overlap with CoreWeave and Crusoe, but Together sells them as part of one lifecycle.
  • Its serving stack gets more throughput from each GPU than naive serving does, and that lets it price competitively and keep margin.
