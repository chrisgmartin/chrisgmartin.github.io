Section B · Inside the model

Embeddings and Position

Chapter 01 produced ids. This chapter covers how they become vectors in the residual stream, how the model learns where each token sits (learned positions, RoPE, ALiBi), how context windows are extended, why long contexts degrade, and what 131,072 tokens of context costs in memory.

The embedding matrix, and the output matrix that may be the same one

Chapter 01 ended with a list of integers. The model's first operation is a table lookup. The embedding matrix has one row per vocabulary entry and one column per hidden dimension, so Llama 3.1 8B holds 128,256 rows of 4,096 numbers, 525,336,576 parameters in all. Token id 6151 selects row 6151, and that row is the vector the first layer receives. Nothing is computed. The 1,421 tokens of Harbourline's help-centre prompt become a 1,421 × 4,096 grid, one row per position, and everything the network does from here is an operation on that grid.

At the other end sits the output matrix, which turns the final vector at a position into one score per vocabulary entry. It has the same shape as the embedding table, and Vaswani et al. (2017) share one weight matrix between the two embedding layers and the pre-softmax projection. Press and Wolf (2016) recommend tying them, reporting better perplexity and, for translation models, a size cut to less than half. Llama 3.1 8B sets tie_word_embeddings to false and keeps two separate 525-million-parameter matrices. The Llama 3.2 1B configuration sets it to true, which at hidden size 2,048 saves 128,256 × 2,048 ≈ 263 million parameters, a large share of a model that small. Tying pays most where the vocabulary is large against the hidden size, and costs some freedom, since one matrix must serve as both input code and output scoring. Chapter 05 covers what happens to those scores.

Retrieval systems use the same idea with a model built for the purpose: see Embeddings in the RAG guide.

The residual stream

After the lookup, each position carries a 4,096-number vector, and this vector is the object every later component reads and writes. Elhage et al. (2021), in the transformer-circuits framework, call it the residual stream: the token embedding, every attention head, every feed-forward layer and the final output projection communicate by reading from and writing to different subspaces of it. A layer does not replace the vector. It computes an update and adds it.

position t: embed(token_t) | v stream ---- attention reads it, adds a delta ----+ ^ | +---------------------------------------------+ | stream ---- feed-forward reads it, adds a delta -+ ^ | +---------------------------------------------+ | ... 32 layers, each adding to the same 4,096 numbers ... | v output matrix -> 128,256 scores

Two things follow. The hidden size is the bandwidth of the whole model: every fact that reaches the output travels in 4,096 numbers per position. And nothing in the stream says where a token sits, so the customer disputed the claim and the claim disputed the customer would give attention the same set of vectors. Position has to be injected.

Absolute positions: sinusoidal and learned

The original transformer adds a position vector to each embedding before the first layer. Vaswani et al. build it from sines and cosines, PE(pos, 2i) = sin(pos / 10000^(2i/d)) and the matching cosine, with wavelengths in a geometric progression from 2π to 10000·2π. They chose it because for any fixed offset k, the encoding at pos + k is a linear function of the one at pos, which they hoped would let the model attend by relative position. They also tried learned position embeddings, a table with one trained row per position, and found nearly identical results.

GPT-2 took the learned route with 1,024 rows (its configuration lists n_positions of 1,024). That is a hard limit: position 1,025 has no row. Absolute schemes also treat positions 5 and 105 as unrelated, when language usually cares about distance between tokens. So current decoders moved the position signal into attention.

RoPE: position as rotation

Rotary position embedding, from Su et al., encodes absolute position with a rotation matrix and, in the same step, makes the attention score depend on relative position. Llama 3.1, Qwen3 and DeepSeek-V3 all list a rope_theta in their configurations. The model leaves the residual stream alone and rotates the query and key vectors, inside attention, by an angle proportional to position. The head vector is split into consecutive pairs of numbers, and pair i at position m is turned through the angle m × θ_i, with θ_i = base^(-2i/d). For Llama 3.1 the base is 500,000 and d is the head dimension, 128, so there are 64 pairs.

Relative position follows from geometry. Rotating two vectors by the same angle leaves their dot product unchanged, so the score between a query at position m and a key at position n depends only on m − n. The script checks it on random vectors.

rope_demo.py
import numpy as np

def rope(x, pos, theta=500_000.0):
    """Rotate each consecutive pair (x[2i], x[2i+1]) by pos * theta**(-2i/d)."""
    d = len(x)
    ang = pos * theta ** (-np.arange(0, d, 2) / d)
    c, s = np.cos(ang), np.sin(ang)
    out = np.empty_like(x)
    out[0::2] = x[0::2] * c - x[1::2] * s
    out[1::2] = x[0::2] * s + x[1::2] * c
    return out

rng = np.random.default_rng(0)
q, k = rng.normal(size=128), rng.normal(size=128)       # one Llama 3.1 head dimension
for m, n in [(5, 2), (105, 102), (80_005, 80_002), (5, 3)]:
    print(f"query at {m:>6}, key at {n:>6}, offset {m - n}:  score {rope(q, m) @ rope(k, n):9.4f}")
print(f"no rotation:                              score {q @ k:9.4f}")
query at      5, key at      2, offset 3:  score   3.2660
query at    105, key at    102, offset 3:  score   3.2660
query at  80005, key at  80002, offset 3:  score   3.2660
query at      5, key at      3, offset 2:  score   2.1906
no rotation:                              score   0.3463

The first three lines share an offset and a score. The 64 pairs turn at different speeds. For Llama 3.1 the fastest completes a turn every 6.28 tokens and the slowest every 2,559,196 tokens, so the high-frequency pairs resolve neighbouring tokens and the low-frequency pairs barely move across an entire document. Su et al. also show the score decaying with relative distance. RoPE has no table and no hard length limit, since the rotation can be computed for any m. What it lacks is any guarantee that the model behaves sensibly at angles it never saw in training.

ALiBi: position as a penalty

Press, Smith and Lewis (2022) removed position vectors altogether. Attention with Linear Biases subtracts from each query-key score a penalty proportional to their distance, with a slope fixed per head before training. For 8 heads the slopes are the geometric sequence 1/2, 1/4, down to 1/256. A 1.3-billion-parameter model trained on length 1,024 extrapolated to 2,048 with the perplexity of a sinusoidal model trained on 2,048, training 11% faster and using 11% less memory. The cost is a strong recency bias. The open-weight models named in this guide use RoPE instead, so ALiBi matters mainly if you pretrain your own model short and run it longer.

Extending the window: interpolation, YaRN and Llama 3.1's recipe

A RoPE model trained to 8,192 tokens has never seen the angles that positions 8,193 and beyond produce, and Chen et al. (2023) report that extrapolating there can give catastrophically high attention scores. Their position interpolation instead rescales the position indices linearly down to the trained range, so position 32,768 of a model trained on 2,048 is treated as 2,048. They extended LLaMA models to 32,768 tokens with fine-tuning within 1,000 steps. YaRN (Peng et al., 2023) is a further RoPE extension method, and its abstract reports needing 10 times fewer tokens and 2.5 times fewer training steps than earlier methods.

The Llama 3.1 configuration applies a related idea, which its rope_scaling block names: factor 8, a low-frequency factor of 1, a high-frequency factor of 4, and an original length of 8,192. Hugging Face's implementation sorts each of the 64 pairs by wavelength. A wavelength under 8,192/4 = 2,048 tokens is left alone, one over 8,192 has its frequency divided by 8, and the band between is blended. Running the same arithmetic on the 64 pairs gives 29 left alone, 6 blended and 29 divided by 8, and the slowest wavelength rises from 2.56 million to about 20.5 million tokens. Fast pairs keep their resolution for local detail, and the slow pairs, which carry coarse position across the document, are stretched eightfold.

Scaling alone is not how the window was won. The Llama 3 paper says it trained on long sequences only in the final stages of pre-training, because attention compute grows quadratically in length, increasing the context gradually in six stages from 8K to 128K over about 800 billion tokens for the 405B model, and judging each stage on recovered short-context scores and perfect needle-in-a-haystack retrieval up to that length. So 131,072 is a training programme plus a position recipe, not a switch, and a model you extend yourself with a small fine-tune should be expected to lag one trained for it.

Why long contexts degrade

Fitting in the window and using it well are separate. Liu et al. (2023) tested multi-document question answering and key-value retrieval and found performance often highest when the relevant information sits at the start or end of the input and significantly lower in the middle, a U-shaped curve that also appeared in explicitly long-context models. They show the effect, not its cause, and I know of no settled mechanism. For Harbourline it is a placement rule. A 300-page policy cannot be pasted whole, but even the eight passages of a RAG prompt are subject to it. Put the schedule passage that holds the deductible at the edges of the context, a point the RAG guide's context-assembly chapter develops.

Needle-in-a-haystack tests, which hide one fact in long filler and ask for it back, measure only retrieval of an isolated string. Hsieh et al. (2024) built RULER because, in their words, that test indicates only a superficial form of long-context understanding. Their 17 models all claimed 32K tokens or more, nearly all scored near perfectly on the plain needle test, and yet only about half kept satisfactory performance at 32K once tasks required multiple needles, tracing or aggregation. A claimed context length is the longest input the model accepts. The length at which your task still works is a number you measure with your own documents, using the evals guide.

What 131,072 tokens costs

Every position keeps a key and a value vector at every layer for later tokens to attend to; chapter 03 derives why only 8 key-value heads are kept. For Llama 3.1 8B in BF16 that is 2 × 32 layers × 8 heads × 128 × 2 bytes = 131,072 bytes per token. Filling the window therefore costs 131,072 tokens × 131,072 bytes = 17,179,869,184 bytes, exactly 16 GiB, or 17.2 GB, for one sequence.

An 80 GB H100 holds the 16.1 GB of weights and then (80 − 16.1) / 17.2 = 3.7, so at most three full-window sequences, before activations and runtime overhead take their share. The window is a memory budget as much as a quality claim. Reading 17.2 GB of cache once at the card's 3.35 TB/s memory bandwidth takes 17.2 / 3350 ≈ 5.1 ms, a floor that applies to every decode step of such a sequence. The PagedAttention guide is about managing exactly this memory.

The Harbourline document uploader accepts policies of up to 300 pages. At an assumed 500 words a page and 1.23 tokens per word, the ratio measured on the prompt in chapter 01, that is about 185,000 tokens, which exceeds 131,072 before a question is added. At an illustrative $2 per million input tokens, a full window costs about $0.26 per request, every time. The case for the long window is a task that needs the whole document at once, such as comparing two versions of a wording. For a question about one deductible, retrieving a few passages beats paying for 131,072 tokens and then relying on the model to find one fact in the middle.

✓ Check yourself

Answer from memory first.

  1. Llama 3.1 8B has a 128,256 × 4,096 embedding table and a separate output matrix of the same shape. A colleague proposes tying them to "save 0.5 billion parameters". What do you check before agreeing, and what do you expect to lose?

    Show answer

    Tying means one matrix serves as both the input lookup and the output scoring, so the saving is real (525 million parameters) but the model must be trained that way: an existing checkpoint with untied weights cannot simply be tied. You also give up the freedom for input and output representations to differ. See The embedding matrix.

  2. Why does the model need position information at all, given that attention can already see every earlier token?

    Show answer

    Attention compares vectors and sums over them, and neither step depends on order. Two sentences with the same words in a different order produce the same set of embeddings, so without a position signal the model cannot tell them apart. See The residual stream.

  3. You rotate a query by 40 positions' worth of angle and a key by 37 positions' worth. A second pair sits at positions 9,040 and 9,037. Which has the larger attention score, and why does that make RoPE attractive for long inputs?

    Show answer

    They are equal, since the score depends only on the offset of 3. No table of positions exists to run out, so the same learned behaviour applies wherever the pair sits. See RoPE.

  4. A vendor says its model "supports 128K tokens" and passes a needle-in-a-haystack test at every length. You plan to put 100K tokens of claim history into the claims-intake agent. What do you do before trusting it?

    Show answer

    Test your own task at your own length, with the evidence placed at the start, middle and end. The needle test shows that a lone string can be retrieved, and RULER found that models claiming 32K or more mostly degraded on harder tasks well before their claimed length. See Why long contexts degrade.

  5. Harbourline wants every chat request to carry the full 300-page policy "so the model never misses anything". Make the case against it using only numbers from this chapter, and name one task where you would agree.

    Show answer

    About 185,000 tokens exceeds the 131,072 window outright. A full 131,072-token window costs 17.2 GB of KV cache per sequence on an 80 GB card with 16.1 GB of weights, so at most three such requests fit, and the middle of the context is where accuracy tends to fall. Comparing two versions of a policy wording is a task that does need the whole document at once. See What 131,072 tokens costs.

Takeaway

  • The embedding matrix is a lookup table with one trained row per vocabulary entry, and the output matrix has the same shape and may be tied to it.
  • The residual stream is a single vector per position that every attention and feed-forward layer reads and adds a delta to, so its width bounds what the model can carry.
  • Attention is blind to order, so position must be injected: added to embeddings in the original transformer and GPT-2, applied as a rotation to queries and keys in RoPE, or applied as a distance penalty in ALiBi.
  • RoPE rotates each pair of query and key numbers by an angle proportional to position, which makes the attention score depend only on the offset between two tokens.
  • Extending a RoPE model rescales positions or frequencies and still needs training: Llama 3 reached 128K through staged long-sequence pre-training, not through the scaling block alone.
  • Models use the middle of a long context worse than its ends, and a passed needle test does not show that harder tasks work at the claimed length.
  • For Llama 3.1 8B a full 131,072-token window needs 16 GiB of KV cache per sequence, so context length is a memory budget before it is a quality claim.

Further reading

  • A Mathematical Framework for Transformer Circuits — Elhage et al., Anthropic, 2021. Good for the residual stream view of how components read and write.
  • RoFormer: Enhanced Transformer with Rotary Position Embedding — Su et al., 2021. The derivation of RoPE and its relative-position property.
  • Train Short, Test Long: ALiBi — Press, Smith and Lewis, 2022. Good for the linear bias, its slopes and the extrapolation experiment.
  • Extending Context Window of Large Language Models via Position Interpolation — Chen et al., 2023. Why extrapolating RoPE fails and what interpolating changes.
  • YaRN: Efficient Context Window Extension of Large Language Models — Peng et al., 2023. A compute-efficient RoPE extension method and its training budget.
  • Lost in the Middle — Liu et al., 2023. The U-shaped use of position in long contexts and the experiments that show it.
  • RULER: What's the Real Context Size of Your Long-Context Language Models? — Hsieh et al., 2024. Good for claimed against effective context length and the limits of needle tests.
