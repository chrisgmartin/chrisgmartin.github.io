Section B · Inside the model

Attention, One Head at a Time

Chapter 02 gave every position a vector and a sense of where it sits. This chapter takes attention one head at a time: queries, keys and values, a worked three-token example with the numbers shown, the causal mask, multi-head and grouped-query attention with the KV-cache arithmetic, the quadratic cost, and what heads turn out to do.

What one head computes

When the model reaches windscreen in Harbourline's question, the vector at that position knows little beyond the word. To produce the right next token it needs the policy number thirty tokens later, the deductible in a retrieved passage a thousand tokens earlier, and the instruction in the system prompt. Attention is the only mechanism that moves information between positions. Each position issues a query, every earlier position offers a key to be matched against, and a position whose key matches well contributes its value to the result. The output at each position is a weighted average of value vectors, with weights set by how well queries and keys match. Everything else in a transformer works on one position at a time.

Query, key and value are three linear views of the same residual-stream vector, so what a token asks for can differ from what it advertises and from what it hands over.

The three projections, with Llama 3.1's shapes

Each projection is a learned matrix. With x the residual-stream vector of one position, q = x·W_Q, k = x·W_K and v = x·W_V. For Llama 3.1 8B (hidden size 4,096, 32 query heads, 8 key-value heads, head dimension 128) the shapes are:

A worked example with three tokens

Take three tokens, windscreen, damage, excess, a model width of 4 and a head dimension d_k of 2. The matrices are made-up integers; a real model learns them.

attn_demo.py
import numpy as np
np.set_printoptions(precision=3, suppress=True)

tokens = ["windscreen", "damage", "excess"]
X = np.array([[1, 0, 1, 0],        # one row per token: d_model = 4
              [0, 2, 0, 1],
              [1, 1, 1, 1]], dtype=float)
Wq = np.array([[1, 0], [0, 1], [1, 0], [0, 1]], dtype=float)   # d_model x d_k, d_k = 2
Wk = np.array([[1, 0], [0, 1], [0, 1], [1, 0]], dtype=float)
Wv = np.array([[1, 0], [0, 1], [1, 1], [0, 0]], dtype=float)

Q, K, V = X @ Wq, X @ Wk, X @ Wv
scores = Q @ K.T / np.sqrt(Q.shape[1])                 # 3 x 3, scaled by sqrt(d_k)
mask = np.triu(np.ones_like(scores), k=1).astype(bool)  # True above the diagonal = future
masked = np.where(mask, -np.inf, scores)
weights = np.exp(masked - masked.max(axis=1, keepdims=True))
weights /= weights.sum(axis=1, keepdims=True)
out = weights @ V

for name, m in [("Q", Q), ("K", K), ("V", V), ("scores", scores), ("weights", weights), ("output", out)]:
    print(name); print(m)

The script prints the six matrices one under another, and the block above lays them side by side with the same values, one row per token. Walk through the second row, damage. Its query is [0, 3]. Dotted with the three keys [1, 1], [1, 2] and [2, 2] it gives 3, 6 and 6, and dividing by √2 gives 2.121, 4.243 and 4.243. The causal mask then removes the third score, since excess comes later. What remains is a softmax over [2.121, 4.243]: e2.121 = 8.34 and e4.243 = 69.6, so the weights are 8.34 / 77.9 = 0.107 and 69.6 / 77.9 = 0.893. The output is 0.107 × [2, 1] + 0.893 × [0, 2] = [0.214, 1.893], mostly the value of damage itself with a little of windscreen mixed in.

The division by √d_k is there for a reason Vaswani et al. give: for large d_k the dot products grow large in magnitude and push the softmax into regions with extremely small gradients. A quick check shows the size of the effect. For random vectors with unit-variance entries, the standard deviation of a dot product is 1.41 at d_k = 2 and 11.3 at d_k = 128, Llama's head dimension. Divided by √d_k it is 1.0 in both cases. Without it, score gaps of ten or more make the softmax nearly one-hot from the first step of training.

The causal mask and the softmax

Two operations shape the weights. The causal mask sets every score above the diagonal to minus infinity before the softmax, so position t can attend to positions 0 through t and never to later ones. Exponentiating minus infinity gives zero, which is how the third column of damage's row vanished. The mask is what makes next-token training possible in one pass: all positions are computed at once, and each is still predicting the token after it using only what came before. Chapter 06 shows what the mask lets the server cache.

The softmax turns each row of scores into weights that are positive and sum to 1, so the output is always a convex combination of values. Softmax is sharp: a gap of two in the scores already gives 0.89 against 0.11. And weights must sum to 1, so a head with nothing relevant to read still has to put its weight somewhere. Xiao et al. (2023) observed that models put strong attention on the initial tokens even when those tokens carry no meaning, calling them attention sinks, and showed that a sliding window which drops the first tokens' keys and values fails once the text outgrows the cache. Keeping them largely restores quality.

Many heads, and the output projection

A single head makes one weighted average per position. Vaswani et al. run several in parallel, each with its own W_Q, W_K and W_V, so the model can track several relations at once. Llama 3.1 8B runs 32 query heads of dimension 128 per layer. Their outputs are concatenated into a 4,096-number vector and multiplied by W_O, shape 4,096 × 4,096, which mixes the heads and writes the result back into the residual stream as an additive update. Elhage et al. note that this concatenate-and-multiply form is mathematically equivalent to treating each head as an independent operation whose result is added to the stream.

residual stream x (4,096) | +--> head 0 : q,k,v (128 each) --> weighted values (128) --+ +--> head 1 : ... | +--> ... +--> concat (4,096) +--> head 31 : ... | | | +-------+ | v | x W_O (4,096 x 4,096) v | x + update <----------------------------------------------------------+

Heads in a layer cannot see each other's output until the next layer, so depth is how a later head uses what an earlier one found.

MQA and GQA: sharing keys and values

During generation, the keys and values of every earlier token are kept and reloaded at each step, and that traffic limits decoding. Shazeer (2019) proposed multi-query attention: all query heads share a single key head and a single value head, which shrinks those tensors and the memory bandwidth to read them, at the price of minor quality degradation. Ainslie et al. (2023) introduced grouped-query attention, which uses an intermediate number of key-value heads, more than one and fewer than the query heads, and report quality close to multi-head attention at speed comparable to multi-query. Llama 3.1 8B is a GQA model: 32 query heads in 8 groups of 4, each group sharing one key head and one value head. The saving is direct, because the cache stores keys and values, not queries.

The formula is 2 (K and V) × 32 layers × KV heads × 128 × 2 bytes, as in chapter 02. With 32 KV heads the Llama 3.1 cache would be four times larger: 64 GiB per full-window sequence, which would not fit on an 80 GB H100 beside the 16.1 GB of weights. That is the reason the architecture exists. Eight groups sit between the extremes: Shazeer reports a quality cost for a single shared head, and Ainslie et al. report that an intermediate count stays close to full multi-head quality. See Attention and KV-Cache Optimisations for the serving side. The trade flips for a small model at short context, where the cache is negligible and only the quality cost remains.

The quadratic cost

Every query is scored against every earlier key, so a sequence of n tokens produces n² scores per head per layer. Counting multiply-adds as 2 FLOPs, the scores (QKT) and the weighted sum of values together cost about 4 × n² × 4,096 FLOPs per layer, with 4,096 being heads times head dimension, and the model has 32 layers. The rest of the forward pass, the weight matrices, costs about 2 × 8.03 billion FLOPs per token, a figure chapter 04 derives. Put the two side by side for the Harbourline prompt and for a full window:

The two terms cross at n = 2N / (4 × 4,096 × 32) ≈ 30,600 tokens. A causal mask means only about half the scores are needed, so a kernel that skips the masked half crosses near 61,000. Harbourline's chat prompt is far below that and dominated by the weights. Above it the quadratic term takes over, which is why the Llama 3 paper trains on long sequences only in the final stages. The table counts compute only; memory is the other quadratic. At n = 131,072 one head's score matrix has 17.2 billion entries, about 34 GB in BF16 if stored, far more than a card holds. FlashAttention (Dao et al., 2022) computes exact attention by tiling, reducing reads and writes between GPU high-bandwidth memory and on-chip memory, so the full matrix is never written out. These are estimates of order of magnitude, not a benchmark.

What heads turn out to do

Most heads are not cleanly interpretable. Two kinds have been studied closely. A previous-token head attends mostly to the position just before the current one and copies information from it. An induction head uses what previous-token heads wrote. Olsson et al. (2022) define the circuit as a rule: given a sequence that contained [A][B] earlier and now reaches [A], predict [B]. The mechanism has two heads. The first, in an earlier layer, copies each token's identity onto the token after it. The second looks for positions whose recorded predecessor matches the current token, attends there, and copies what follows. That composition across layers is why the paper notes that induction heads do not occur in one-layer models.

The practical relevance is in-context behaviour. If a Harbourline prompt contains a policy number, and the model must reproduce it in its answer, a circuit that finds the earlier occurrence and copies what comes next is plausibly the machinery, though I know of no study that shows it for this case. Olsson et al. find that induction heads form in an abrupt phase change early in training, when in-context learning improves. Read the strength of that claim carefully: the paper rates its evidence as stronger for small attention-only models, and for large models with feed-forward layers it states that it must rely mainly on correlational evidence which could be confounded. Heads are a lens for reading a model, not a spec. Do not assume a given head in a given checkpoint plays a named role. Chapter 09 returns to what interpretability can and cannot offer.

✓ Check yourself

Answer from memory first.

  1. In the worked example, the query for damage scores equally (4.243) against itself and against excess before masking, yet the weight on excess is 0. Where did the difference come from, and what would break if you removed it during training?

    Show answer

    The causal mask set the score for excess to minus infinity before the softmax, so its weight is exactly zero. Without it, each position would read the tokens that follow it, and since training predicts the next token at every position at once, the model could copy the answer from the future and learn nothing useful. See The causal mask and the softmax.

  2. A colleague removes the 1/√d_k factor from a 128-dimensional head "to save a division". Describe what the attention weights look like at the start of training and why learning suffers.

    Show answer

    Dot products of unit-variance vectors have a standard deviation near 11 at d_k = 128, so score gaps are large and the softmax is close to one-hot. A saturated softmax has tiny gradients away from its peak, so the head learns slowly and cannot easily redistribute its attention. See A worked example.

  3. You are sizing a deployment of a model with 32 query heads, 32 layers and head dimension 128 in BF16. Compare the KV cache per token with 32 KV heads against 4 KV heads, and say what the second buys at 100,000 tokens.

    Show answer

    Per token it is 2 × 32 × heads × 128 × 2 bytes, so 524,288 bytes against 65,536, an eightfold cut. At 100,000 tokens that is about 52 GB against 6.6 GB per sequence, which decides whether one card can hold several long sequences or one. The cost is some quality, as the GQA paper reports. See MQA and GQA.

  4. A prompt grows from 2,000 to 20,000 tokens. Does attention compute grow tenfold or a hundredfold, and does the total cost of the forward pass grow by the same factor?

    Show answer

    Attention compute grows a hundredfold because it scales with n². The total grows by less than that, between tenfold and a hundredfold, since the weight matrices cost per token and scale only tenfold. Below about 30,600 tokens for Llama 3.1 8B they are the larger share. See The quadratic cost.

  5. Someone explains the model's habit of repeating a policy number from the prompt by pointing at "the induction head in layer 12". What do you say?

    Show answer

    Induction heads are a documented circuit, a previous-token head composed with a later head, and plausible machinery for copying. But the original evidence is correlational for large models, and naming a specific head in a specific checkpoint requires an experiment on that checkpoint, such as ablating it and measuring the copy rate. Without that it is a hypothesis. See What heads turn out to do.

Takeaway

  • Attention is the only mechanism that moves information between positions: each position's output is a weighted average of earlier positions' values, weighted by how well its query matches their keys.
  • Scores are scaled by 1/√d_k so that dot products stay near unit size and the softmax does not saturate.
  • The causal mask zeroes the weights on later positions, which lets training compute every position's next-token prediction in one pass.
  • Heads run in parallel on different slices of the projections, and a final output matrix mixes them and adds the result to the residual stream.
  • Grouped-query attention shares keys and values across groups of query heads: Llama 3.1 8B keeps 8 KV heads instead of 32, which cuts its cache from 524,288 to 131,072 bytes per token.
  • Attention compute grows with the square of sequence length and overtakes the weight matrices near 30,600 tokens for this model, so long prompts are limited by it in both compute and cache memory.
  • Previous-token and induction heads are real, documented circuits, but treat any claim about a named head in a named checkpoint as a hypothesis until it is tested.
