Section A · Orient

Start Here

A language model does one thing: given a sequence of tokens, it produces a probability for every token that could come next, and a sampler picks one. Everything else, from context windows to prices to the reasons answers go wrong, follows from how that one step is built. Start here for the map of the guide, the model and prompt every chapter works on, and the vocabulary.

Why the mechanism, and why with numbers

Most engineers who use language models daily carry a working picture of them made of metaphors: the model "reads" the prompt, "understands" the question, "knows" or "forgets" things. The metaphors are good enough to write a prompt and bad enough to make expensive mistakes: paying for a 128k context that the model cannot use well, setting a temperature without knowing what it divides, being surprised that a model cannot count the letters in a word or that the same request costs more in Finnish than in English. Each of those has a mechanical explanation that fits in a paragraph once you know what a token, an attention head and a logit are.

This guide explains the mechanism with arithmetic rather than metaphor, in the style of PagedAttention from First Principles. Every chapter works on one model and one prompt, so a number computed in chapter 01 is reused in chapter 06, and every claim about why models behave as they do is tied to a part of the machine you have already seen. It is written for engineers who build on these models, not for people who train them: the goal is that you can read a model card, set generation parameters, estimate a cost and explain a failure without guessing.

The map: text in, one token out

A decoder-only transformer, which is what every current general-purpose language model is, produces one token at a time by running the same pipeline on everything generated so far. The guide walks it left to right and then around the loop.

"What is my deductible for windscreen damage on policy HL-UK-4471-220?" │ tokeniser (ch. 01) ▼ [ 3923, 374, 856, 2219, ... ] integer ids from a vocabulary of 128,256 │ embedding + position (ch. 02) ▼ one vector of 4,096 numbers per token the residual stream │ 32 × [ attention (ch. 03) → feed-forward (ch. 04) ] ▼ logits: 128,256 scores for the next token (ch. 05: softmax, temperature, top-p → one id) │ ▼ append the chosen token, cache what was computed, go again (ch. 06) ──┐ ▲ │ └───────────────────────────────────────────────────────────────────┘

Three facts about this loop explain most of what practitioners meet. The model sees ids, not characters, so anything about spelling, counting or arithmetic on digits is at the mercy of how the text was cut into tokens. Every token attends to every earlier token, so cost grows with the square of the sequence length unless the intermediate results are cached, which is what the key-value cache is for and why serving systems are built around it. And the output is a distribution, not an answer: the sampler's settings decide how much of that distribution you see, and a model that is wrong is a model whose most probable continuation was wrong, which chapter 09 takes apart.

The worked model and the worked prompt

The guide uses Llama 3.1 8B as its worked model because its configuration is public, its numbers are round enough to compute by hand, and it is representative of the dense decoder-only design that current open-weight models share. The figures below come from the model's published configuration; chapter 08 reads them from the file and compares them with a current model.

The worked prompt is Harbourline's. Harbourline is a fictional mid-size property-and-casualty insurer, about two million policies in the US and UK, shared with the other AI Engineering guides. Its help-centre assistant sends a system prompt of about 1,200 tokens, two retrieved passages, and a customer question; the one above about a windscreen deductible is used throughout. Two generation settings are contrasted in every chapter that touches sampling: claims extraction at temperature 0 with a JSON schema and a 400-token limit, and the help-centre chat at temperature 0.7 and top-p 0.9, streamed. The figures that describe Harbourline are illustrative; the figures that describe the model are not.

The vocabulary

TermMeaning here
TokenAn integer id for a piece of text, usually a word fragment. The unit the model sees, counts and is priced in.
TokeniserThe deterministic procedure that cuts text into tokens and back. Fixed before training; part of the model.
EmbeddingThe vector a token id is mapped to at the input; the start of the residual stream.
Residual streamThe running vector for each position that every layer reads from and adds to.
Attention headOne unit that lets a position gather information from earlier positions, weighted by a learned notion of relevance.
KV head, GQAThe key and value projections shared by several query heads under grouped-query attention.
Feed-forward networkThe per-position layer that holds most of the parameters; where much of the model's knowledge sits.
LogitsThe raw scores over the vocabulary for the next token, before softmax.
Temperature, top-p, top-kWays of reshaping or truncating the next-token distribution before sampling.
Prefill, decodeThe pass over the prompt, then the one-token-at-a-time passes that follow.
KV cacheThe stored keys and values for every earlier token, so decode does not recompute them.
Context windowThe longest sequence the model accepts. Effective context, the length it uses well, is shorter.
Mixture of expertsA design where each token uses only some of the feed-forward parameters; total and active parameter counts differ.
Reasoning modelA model trained to generate a working-out before the answer, spending tokens at inference time to improve it.

Takeaway

  • A language model computes a probability for every possible next token and a sampler picks one; the loop repeats, and everything else is detail of that step.
  • The model sees token ids, not characters, so spelling, counting and arithmetic on digits depend on how the text was cut.
  • Every token attends to every earlier one; the key-value cache is what makes that affordable, at 128 KB a token for the worked model.
  • The output is a distribution; temperature and top-p decide how much of it you see, and a wrong answer is a probable continuation that happened to be false.
  • One model and one prompt run through the whole guide so that every number can be traced back to the configuration it came from.
