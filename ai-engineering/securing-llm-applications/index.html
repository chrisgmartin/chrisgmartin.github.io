Securing LLM Applications

A threat model for systems whose core component follows instructions found in its data: prompt injection direct and indirect, jailbreaks, agents with too much agency, leakage, poisoned weights and training data, the defences that hold and the ones that only feel like they do, red teaming as an eval, and what to do when an attack lands.

Section B · Threats
01 The Threat Model Assets, actors and trust boundaries for an LLM system, why the model cannot separate data from instructions, the OWASP Top 10 for LLM Applications mapped to Harbourline's six surfaces, and how to rank what to fix first. 02 Prompt Injection Direct and indirect injection with the mechanism and the public incidents, why prompt hardening fails, the paths through documents, email, web and tool results, and the Harbourline claim form that tries to change an address. 03 Jailbreaks and Safety Bypass Role-play, encoding, many-shot and multi-turn attacks, adversarial suffixes, what model providers defend against, what an application team must still do, and measuring attack success rate.
Section C · Agents and data
04 Agents, Tools and Excessive Agency The lethal trifecta, confused deputies, tool permissions and confirmation for writes, MCP server trust and tool poisoning, sandboxing code execution, and Harbourline's customer-service agent. 05 Data Leakage and Privacy System prompt extraction, memorisation and training-data extraction, PII in traces and logs, tenancy and cache leaks, exfiltration through rendered output, and output-side controls. 06 Supply Chain, Poisoning and Backdoors Weights, formats and provenance, poisoned fine-tuning data and how little it takes, sleeper behaviours, dependency and MCP package risk, and the controls on Harbourline's fine-tuning pipeline.
Section D · Defence and assurance
07 Defences in Depth Privilege separation and dual-model patterns, input and output classifiers, spotlighting and structured tool results, allowlists, rate limits and canaries, and an honest account of what each defence stops. 08 Red Teaming and Evaluation Manual and automated red teaming, attack success rate as an eval metric, adversarial benchmarks for agents, continuous testing in CI, bug bounties, and the permit decision at Harbourline. 09 Governance and Incident Response Logging for forensics, the incident playbook for an injection that landed, disclosure, and the regulation and standards an application team must map to as of November 2026.
