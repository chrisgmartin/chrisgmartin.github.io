SkillSpector

NVIDIA's security scanner for agent skills — static analysis, optional LLM review and a skill-inspector skill that answers one question: is this safe to install?

by NVIDIArepo github.com/NVIDIA/SkillSpectorlicense Apache-2.0skills 1 + CLIchecked September 2026

What it is

The other three entries on this page are collections you install. This one is the tool you run before you install them. A skill is a folder of instructions and scripts that your agent loads and acts on — it is executable input with no review step, and the other collections here are no exception. SkillSpector scans a skill folder, repo URL or zip and returns a 0–100 risk score with a recommendation; the bundled skill-inspector skill then teaches the agent to run that scan and read the source around every finding rather than trusting the number.

Install

CLI (uv)

Python 3.12+. Installs a skillspector binary on your PATH.

shell
uv tool install git+https://github.com/NVIDIA/skillspector.git
uv tool update skillspector

# with the MCP server extra, if you want to expose it to an agent
uv tool install 'skillspector[mcp] @ git+https://github.com/NVIDIA/skillspector.git'

Skill folder

Drop the skill where your agent looks for skills — no plugin marketplace involved.

shell
git clone --depth 1 https://github.com/NVIDIA/SkillSpector /tmp/skillspector
cp -r /tmp/skillspector/skills/skill-inspector ~/.claude/skills/

Docker (no Python)

Built locally from the repo's Dockerfile; mount the directory you want scanned at /scan.

shell
make docker-build
docker run --rm -v "$PWD:/scan" skillspector scan ./my-skill/ --no-llm

The skill 1 skill

SkillWhat it does · when it triggers
skill-inspectorPre-install review — Triggers when you ask whether a skill or downloaded folder is safe, trustworthy, installable, over-permissioned or malicious. Runs two independent review lines — the SkillSpector static scan, then a source-aware read of intent, permission fit and hidden behaviour — and returns APPROVE, CAUTION or REJECT. Treats the target as untrusted: read-only inspection, never executes the target's scripts, and refuses to downgrade an unexplained HIGH or CRITICAL on reputation alone.SKILL.md

What it detects

71 patterns across 17 categories. The first group is what an attacker does to your agent through a skill; the second is what the skill's own code does.

Running it

Input can be a directory, a single SKILL.md, a zip or a git URL. Output is terminal, JSON, Markdown or SARIF — the last one drops straight into CI code scanning.

shell
# one skill, static only — no API key, no network round-trip
skillspector scan ./my-skill/ --no-llm

# a whole skills directory: each subfolder with a SKILL.md scanned independently
skillspector scan ~/.claude/skills --recursive --no-llm

# straight from the source you were about to install
skillspector scan https://github.com/user/some-skill

# machine-readable, and fail the build on findings
skillspector scan ./my-skill/ --format sarif --output skills.sarif --fail-on-findings

Without --no-llm a second semantic pass runs against a provider of your choice. claude_cli, codex_cli, gemini_cli and opencode_cli reuse your existing CLI login, so you can get the semantic pass without provisioning an API key:

shell
SKILLSPECTOR_PROVIDER=claude_cli skillspector scan ./my-skill/

Three commands in total: scan, baseline (write a suppression file for findings you have already judged), and mcp (serve the scanner to an agent as an MCP tool).

Reading a report

The score is evidence, not a verdict

Static pattern matching over prose is noisy in both directions, and the skill's own instructions say not to lean on the number. Scanning a directory of well-known, reputable skills will return CRITICAL and DO_NOT_INSTALL, because a documented rm -f ./out.docx matches "tool parameter abuse", os.environ.copy() passed to a subprocess matches "environment-variable harvesting", the phrase "don't apologize" matches "anti-refusal", and a skill that documents MCP tool schemas matches the tool-poisoning YARA rule. A security skill scores CRITICAL for discussing exploits. Read the finding and the source around it before you act on the label.

What earns attention, in rough order:

  • Supply chain findings with a file attached — shipped .pyc, a __pycache__/ directory, any executable artifact normal review skips. Check whether a .pyc has a matching .py: an orphan is importable with no reviewable source, which is the actual attack. A .pyc whose header mtime and size match its source is a committed build artifact — untidy, not hostile.
  • Exfiltration with a real destination — a hard-coded host in a script beats any keyword match in a documentation file.
  • Findings in SKILL.md and frontmatter rather than in data files. The frontmatter is always loaded; a CSV of UI guidance that happens to contain the string "Allow all domains" is content, not instruction.
  • Anything analysis-evasion flags as (partial) — that is the parser reporting it could not read the whole bundle, so treat it as missing coverage and go look yourself.
Don't trust a shipped baseline

A skill can ship its own .skillspector-baseline.yaml, which would suppress findings in your scan. SkillSpector only reports that it found one unless you pass --use-shipped-baseline. Leave that flag off. Generate your own baseline with skillspector baseline once you have judged the findings yourself.

Notes

  • NVIDIA's stated motivation: in a 31,132-skill analyzed subset of their research dataset, 26.1% of skills contained vulnerabilities and 5.2% showed likely malicious intent.
  • The scanner is one stage of the NVIDIA Verified Skills pipeline, which scans, evaluates and signs skills before publishing them to the NVIDIA skills catalog.
  • --transitive follows external references a skill points at, one level deep by default — useful when a SKILL.md pulls instructions from a URL at runtime.
  • Ships extensions for Pi and OpenCode, and a --mcp-registry mode for scanning MCP Registry payloads instead of skills.

Category descriptions above are paraphrased from the project README and observed scan output as of September 2026 (v2.11.2); the repo is the source of truth and moves faster than this page.
